# 快客 QuickAI 小程序规划

> 状态：草案，待确认。第 8 节的问题确认后再开发 M1。

## 1. 定位

小程序是快客在微信生态里的**引流入口**，不是网页版的缩小版。

- **触达**：分享卡片、朋友圈海报、社群转发、微信搜一搜、公众号 / 视频号挂载。
- **转化**：游客先看效果，免费体验，一键登录送积分，用完后回到网页版做重度创作和充值。v0.2 再在小程序内开通充值。
- **主打场景**：拿来就用、结果适合分享的轻量创作。
  - **AI 商品图**：拍一张商品照片，生成电商主图或种草图。
  - **灵感广场"做同款"**：看到好看的作品，换成自己的图生成同款。
- **不进小程序**：视频、无限画布、Agent、企业功能、AccessKey 和开放 API。
- **一套代码多端**：uni-app 先发微信小程序，再发抖音小程序（电商卖家集中）。

首页以 [docs/design/PROPOSAL.md](design/PROPOSAL.md) 为准。第一屏放可复刻的例子：去除水印、添加水印、旧照修复、一键高清、路人消失、转 3D、转动漫、转 Q 版。点进去换上自己的照片。去除水印和路人消失走擦除，添加水印在手机上完成，其余走生图。商品图和灵感瀑布流不放第一屏。

## 2. 上线前置条件

下面这些事项决定能不能过审，开发期间要同步办理。规则会调整，以微信公众平台的最新要求为准。

| 事项 | 说明 | 负责 |
|---|---|---|
| 小程序主体 | 建议用企业主体。个人主体不能开通微信支付，AI 类目也更难通过审核 | 你 |
| ICP 备案 | 小程序须完成备案才能上线 | 你 |
| 生成式 AI（深度合成）类目资质 | 提供 AI 生图的小程序，审核时常被要求补充深度合成类目资质，如算法备案，或所用大模型服务方的备案证明加合作协议，且主体要一致 | 你 |
| 可用模型 | 海外模型（gpt-image-2、Gemini 系列等）一般拿不到国内备案材料。小程序渠道建议只开放有国内备案的模型（如火山引擎 Seedream 系列），由后端按渠道限制 | 你 + 后端 |
| 服务器域名 | request、uploadFile、downloadFile 的合法域名必须是 HTTPS 且已备案，包括 API 域名和 OSS 图片域名 | 你 |
| 内容安全 | 用户提示词和上传图片需要过微信内容安全接口（`msgSecCheck`、`mediaCheckAsync`），否则审核和运营风险都高 | 后端 |
| 隐私保护指引 | 在后台声明选择图片、保存到相册等用途 | 你 |
| 充值 | 积分属于虚拟商品。微信 2025 年 11 月宣布小程序 iOS 端支持虚拟支付（苹果抽成 15%），开通条件和费率以官方为准。v0.1 不做充值 | v0.2 |

## 3. MVP 范围（v0.1）

| 页面 | 功能 | 登录 |
|---|---|---|
| 首页 | 八张玩法例子：去除水印、添加水印、旧照修复、一键高清、路人消失、转 3D、转动漫、转 Q 版 | 游客可看 |
| 复刻 | 旧照、高清和变装：看示例，上传自己的照片，按例子生成 | 需要 |
| 涂抹 | 去除水印、路人消失：涂住要去掉的区域，只补这一块 | 需要 |
| 添加水印 | 在原图上叠一行字，选左下、右下或居中，手机本地完成 | 不需要 |
| AI 商品图 | 上传商品图，选图种。首批四种 1:1：白底主图、场景主图、卖点特写、种草图 | 需要 |
| 结果 | 预览、保存到相册、分享给好友。朋友圈海报（带小程序码）仍在 M2 | 需要 |
| 我的 | 积分余额、我的作品、分享、邮箱账号与网页版互通说明 | 需要 |
| 登录 | 微信一键登录，新用户送注册积分。邮箱登录仍可用 | — |

微信一键登录调用 Java `POST /api/v1/auth/wx-login`，请求 `{ code, referralCode? }`，返回 `{ token, isNew, registration_bonus, user }`。`code` 来自 `uni.login`。小程序身份在 `sys_config`：`product.auth.wechat-app-id`、`product.auth.wechat-app-secret`。邮箱登录和其他接口仍走现有 Node 服务。小程序生图固定走同一个模型，标识只出现在请求体里，不出现在页面、分享和报错文案里。

## 4. 引流闭环

```text
用户 A 生成作品
  → 分享卡片 / 朋友圈海报（路径带模板 id 和 A 的邀请码）
  → 好友 B 打开，游客状态先看效果
  → 点"做同款"，微信一键登录并绑定邀请关系
  → B 得注册积分，A 得邀请奖励（复用现有邀请规则）
  → B 生成后再分享
```

站外入口：

- 小程序名称和简介覆盖"AI 商品图、电商主图、白底图"等搜索词。
- 公众号文章、视频号和抖音内容挂小程序卡片。
- 网页版和 Skill 的预览页放小程序码。

重点指标：分享率、分享带来的新用户、新用户首图生成率、次日留存、跳转网页版后的注册和充值转化。

## 5. 后端改动（Java：zhirui-ai-admin）

接口沿用现有 `{ success, data, error }` 返回格式和 `Authorization: Bearer <token>` 鉴权。

| 接口 | 说明 |
|---|---|
| `POST /api/v1/auth/wx-login` | Java 已提供，小程序微信登录走这个接口。请求 `{ code, nickname?, avatarUrl?, referralCode?, deviceId? }`，返回 `{ token, isNew, registration_bonus, user }`。AppID、AppSecret 在 `sys_config`。规划早期写过的 `/api/auth/wechat-mini/login` 没有实现，不再使用 |
| `POST /api/auth/wechat-mini/bind` | 已有网页账号的用户在小程序里用邮箱密码登录一次，后端把 openid 绑到该账号，积分和作品互通 |
| `GET /api/wechat-mini/qrcode?scene=` | 调 `wxacode.getUnlimited` 生成小程序码，用于海报 |
| 内容安全 | 渠道为小程序时，提示词调 `msgSecCheck`，参考图调 `mediaCheckAsync`；结果图的审核策略待定 |
| 渠道与模型 | 小程序请求带 `X-Client: mp-weixin`；后端按渠道限制可用模型并统计来源 |
| 待确认 | `/api/creative/templates` 是否允许游客访问；`/api/upload/image` 是否接受用户 token |
| v0.2 | 小程序虚拟支付下单和回调发积分 |

## 6. 技术方案

- **框架**：uni-app（Vue 3 + Vite + TypeScript）CLI 工程，用 VS Code 开发，微信开发者工具预览，不依赖 HBuilderX。
- **状态**：Pinia 管理登录态和积分。
- **请求**：`src/api/request.ts` 封装 `uni.request`，返回格式与网页版 `cloudRequest()` 一致；token 存在本地存储，401 时清除并引导登录。
- **上传**：`uni.uploadFile` 调 `/api/upload/image`（与电商套图 Skill 相同）。网页版使用 OSS 直传，后续可统一。
- **平台差异**：分享、海报、保存相册等能力放在 `src/utils/`，用条件编译区分微信和抖音。
- **发布**：微信开发者工具上传体验版后提审；后续可接 `miniprogram-ci` 自动上传。

```text
src/
├── api/        请求封装与各业务接口
├── stores/     Pinia（登录态、积分）
├── pages/      index 灵感 · create 创作 · mine 我的 · login 登录
├── utils/      分享、海报、平台差异
├── static/     图标与图片
├── App.vue     全局样式与主题变量
├── pages.json  路由与 tabBar
└── manifest.json  AppID 与平台配置
```

## 8. 需要你确认

1. 小程序主体（企业 / 个人）和 AppID；是否已有 ICP 备案和深度合成类目资质。
2. 小程序名称。名称影响搜一搜，建议包含"AI 商品图"一类关键词。
3. 小程序渠道开放哪些模型。这直接关系到资质能否通过。
4. 首发主打 AI 商品图、灵感广场做同款，还是两者都上。
5. 是否同意按第 5 节的契约在 Java 项目中实现后端接口。
